# PROMPTS.md — how AI coding agents were used

The brief asks for a description of how coding agents / LLMs were used during development. This log is kept from day one (§11.2 of the design spec).

## Before code existed
The specification `ct-landscape-agent-design.md` was produced agentically: explorer agents mined production drug-development normalization and evaluation patterns, a design agent live-probed the ClinicalTrials.gov API (corpus size, download endpoint, field paths, and the finding that `browseBranches` is schema-only and empty in practice), and the human scoped budget, simplicity bar, and interface choice, then adjudicated review findings across several critique rounds.

## Build sessions (Claude Code, one session per phase)

### Session 1 — 2026-09-04 — Phase 0 scaffold
**Prompt (paraphrased):** "I have a brief (`argon-brief.md`) and design instructions (`ct-landscape-agent-design.md`). Follow the instructions to build the app step by step, with a task list so the session can be interrupted and resumed. Commit and push each contained task directly to `main`. Start with `/init` and a uv environment."

**Actions:** read the spec end to end; `/init` → `CLAUDE.md`; `uv` project with Python 3.12 and the §3 dependency list; `ctl` CLI stub; `TASKS.md` checklist keyed to §11 phases; `.env.example`; gitignore for the raw dump, DuckDB files, and run stores. Verified the installed Pydantic AI (2.x) still exposes every object the spec's agent design relies on.

### Session 1 (cont.) — Phase 1 fetch + ingest
**Prompt shape:** same session, continuing per the TASKS.md checklist; the agent was told to commit each contained task to `main`.

**Actions:** probed the internal download endpoint (HTTP 200, `application/zip`; the Range header is ignored, so the fetch is a straight stream); wrote `fetch.py` with the v2 pager fallback; pulled one live record (NCT02142738) to confirm field shapes before writing the boundary models; wrote `ingest.py` (lean Pydantic models → Arrow → DuckDB, multiprocessing by zip-member chunks) and `db.py`; piloted on 10k members, then ran the full corpus (69 s, 0 parse failures); wrote `scripts/make_fixtures.py` to cut `mini.zip` (rule-picked §2.5 messiness cases) and `demo.zip` (all gold-indication trials + random sample, pruned to stay < 50 MB); tests on hand-built records + the mini fixture. One self-inflicted bug caught: `ruff format .` reformatted the Python blocks inside the spec markdown — restored byte-for-byte and excluded `*.md` from ruff.

### Session 1 (cont.) — Phase 2 normalize + views
**Prompt shape:** continue per TASKS.md; the user asked mid-session "Are you committing the work along the way?" (answer: per phase).

**Actions:** pulled real distributions from the full raw index before writing any lexicon (top-level MeSH headings, top intervention names / otherNames, sponsor name shapes incl. the "X, a subsidiary of Y" pattern, arm-type mix); wrote the eight lexicon YAMLs; drug-name cleaner + gates + router with tests for every §2.5 case; asset assembly with union-find + root-level contested veto; arm roles; conditions fold/denoise/area rollup; company suffix-pop + curated groups + declared-parent regexes; population lexicon (~250 entries); `views.sql`; build orchestrator + funnel. Iterated against the demo build twice: (1) brand aliases were "contested" because name variants ("neoadjuvant nivolumab", "lenalidomide dexamethasone") keyed as separate assets → added edge-qualifier stripping and the known-token regimen split; (2) "X placebo" labels leaked → placebo-remnant gate. Performance detour: a single combined regex for the population lexicon was 15× *slower* than per-entry regexes; the literal-trigger prefilter fixed it (4 ms/study). Two self-inflicted bugs: a YAML `on` parsed as boolean; a biosimilar-suffix regex classified "low-dose" as a biologic.

### Session 1 (cont.) — Phase 2.1 refinements + Phase 3a ChEMBL tier
**Actions:** ran the full-corpus build and the Q1/Q2/Q3/Q6/Q7 smoke queries (all sub-second, $0). Inspected the 7k contested aliases: the top of the list was every brand name, each claimed by the real asset in hundreds of trials plus a tail of typos / regimen acronyms / "1 cycle of X" phrases claiming it once → added the dominance rule (≥5 trials, ≥10× the runner-up, every decision logged), gated bare target names used as intervention labels ("PD-1", "EGFR-TKI") and bare dose-form words, and made display surfaces qualifier-stripped ("intravenous MK-3475" → "MK-3475"). Probed the ChEMBL REST API live (7,561 mechanisms), wrote the fetch/cache/exact-fold join with the ambiguity veto in both directions, the shipped-artifact loader, the target vocabulary seed, and the LLM-tier batch module (dry-run/limit/ceiling; no spend without an explicit `ctl enrich llm`). Lesson recorded: patch scripts must not assume pre-format text — two edits silently no-op'd after `ruff format` reflowed lines.

### Session 1 (cont.) — Phase 4 agent
**Actions:** introspected the installed Pydantic AI 2.x (the spec's snippets target ~0.4) before writing any agent code; wrote the gate as a pure function + the §8.4 mutation suite first, then the three tools with the four-layer SQL sandbox (tests include DDL/COPY/read_csv/PRAGMA rejections and the engine-level file block), the schema card, and the agent with `answer_question()`. Offline agent tests use a scripted `FunctionModel` with a streaming adapter so the production streaming path runs unchanged; three API-drift bugs were fixed by reading the installed package rather than guessing (`AgentRunResultEvent` location, `FunctionToolResultEvent.part`, `RunUsage` as a property).

### Session 1 (cont.) — Phase 5 API + chat UI
**Actions:** FastAPI app with the SSE `ask` endpoint wrapping `answer_question()`, a filesystem answer/conversation store (the DuckDB file stays read-only at serve time), conversation-scoped gate sets and tool-payload digests for history; a static single-page UI implementing the §7.6 trust affordances (live timeline, verified-citation table with live phase/status, gate badge, trace panel with coverage footer, permalinks, SQL console). TestClient tests inject a scripted model; `ctl serve --demo` smoke-tested with curl. Caught myself writing made-up SRI hashes for the CDN scripts and removed them (versions stay pinned).

### Session 1 (cont.) — Phase 6 evals
**Actions:** eval core (FLOOR/OBJ/DIAG, pooled set metrics with the pinned edge cases), Pydantic gold loader (`extra="forbid"`), a drafted 14-case gold file whose expectations come from the spec's case table (public knowledge) and are explicitly marked unadjudicated — the human adjudication against the CT.gov oracle is the one step the agent must not do; the harness (live + replay modes, per-case records as replay fixtures, report with id lists); mutation operators moved to `evals/mutate.py`. Found and fixed a real sandbox bug through the harness test: a second sandboxed connection in the same process hit DuckDB's locked configuration.

### Session 1 (cont.) — Phase 7 README
**Actions:** wrote the README from the real funnel in `build_meta` and the smoke-query outputs (no numbers typed from memory); the eval section reports exactly what is verified offline (mutation suite, scripted-agent runs, replay gate) and what is pending the human (gold adjudication, live runs). A live browser check of the UI was skipped because it needed the user to pick a Chrome instance; the front-end was exercised through curl/TestClient instead.

### Session 2 — live runs with the user's API key
**Prompt:** "So I added an anthropic api key to the newly created .env file please continue with the test."

**Actions:** one live §7.7 question first (worked: 8 tool calls, gate 16/16), then the gold-set harness. The first live run failed most cases on *agent-behaviour* defects that no offline test could have caught: a shared DuckDB connection under Pydantic AI's threaded parallel tool calls (phantom "not found"), misses raised as retries, a 24-tool-call cap that Sonnet 5's `get_trial` fan-out hit in one turn, a 16-turn cap exhausted by exhaustive exploration, a 4k output cap truncating a large answer, and an index gap (the demo index predated the ChEMBL artifact). Each was fixed with a regression test or a schema-card rule and re-run; run 2 completed 13/14 with zero grounding violations and a clean offline replay. Two index defects surfaced through answers rather than tests ("Cancer Research UK" → "cancer"; Q3 needing sponsor × condition) and got their own fixes. The LLM tier was dry-run only: spend needs the user's go-ahead.
